Hello from the logit demo

This page is served by a real Django app behind haproxy and nginx -- every request through that chain gets a W3C traceparent minted at the edge, and all four tiers (haproxy, nginx, this app, and logit itself) agree on the same trace id: this app's own request span is a real OpenTelemetry span, exported over OTLP straight to Tempo (deliberately bypassing logit -- not every telemetry leg needs it), alongside its structured access log over syslog through logit as usual.

That covers this page's own document request, but a <script src> or <img> tag can't send an outbound traceparent header -- no JavaScript runs before the browser issues that request -- so haproxy mints each sub-resource request a fresh trace id of its own, unconnected to the page's. The correlation for those has to run backwards instead: haproxy already sends a Server-Timing: traceparent;desc="..." response header on every request, which the browser exposes to JavaScript as PerformanceResourceTiming.serverTiming. The browser instrumentation reads that back and links each resource-load span to the exact logit-minted span -- lifted from a plain haproxy or nginx access log line -- that served it.

This demo is not a production example

This stack exists to show a large portion of logit's functionality in a way that's quick to spin up -- it is not an example of how to run any of this in production. A few of the shortcuts that make that possible, so you don't copy them uncritically:

  • Grafana's anonymous access, below, is admin-level, not just read-only (GF_AUTH_ANONYMOUS_ORG_ROLE: Admin, demo/compose.yaml).
  • A hardcoded Django SECRET_KEY (demo/app/demoproj/settings.py) and a hardcoded InfluxDB admin token, INFLUXDB_TOKEN (demo/compose.yaml) -- both already called out in comments where they live; this is just the one place a visitor sees them collected.
  • ALLOWED_HOSTS = ["*"] (same settings.py) -- there's no one real hostname to pin for a stack that answers on localhost at whatever port you gave it.
  • logit itself runs as root, specifically so it can read Docker's own container log directory directly for nginx's access log (docker_in, see demo/README.md) -- real cost paid for one tier's telemetry, not a default posture.
  • Postgres logs every statement (log_min_duration_statement=0, demo/compose.yaml) instead of sampling slow ones -- shows the mechanism, not a production logging policy.
  • No TLS between any of the tiers.
  • Every volume here is disposable -- docker compose down -v wipes all of it, and none of it is backed up.

Generate some traffic by hand

traffic (demo/compose.yaml) already drives a low-volume loop through these, but you can trigger them directly too: /work (jittered latency, an occasional real 503) and /boom (always a real 500, with a real exception recorded on its OpenTelemetry span) -- both give the demo's Tempo traces a shape worth looking at, instead of a flat chain of 200s. traffic itself is a plain curl loop -- no browser involved -- so any browser-originated telemetry only shows up once a person actually opens this page in one.

Unlike the plain link above, this goes through @opentelemetry/instrumentation-fetch (browser/telemetry.js) -- the resulting fetch span becomes a real parent of this call's own Django request span, one trace spanning browser → haproxy → nginx → app → Postgres/Celery.
