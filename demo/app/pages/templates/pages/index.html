Hello from the logit demo

This page is served by a real Django app behind haproxy and nginx. Every request through that chain gets a W3C traceparent minted at the edge, and all four tiers (haproxy, nginx, this app, and logit itself) agree on the same trace id. This app's request span is a real OpenTelemetry span, exported over OTLP straight to Tempo. It deliberately bypasses logit, because not every telemetry leg needs it. The app's structured access log still goes over syslog through logit.

See it in Grafana

  1. Open {{ grafana_url }}. Anonymous access is on, so there's no login.
  2. Go to Dashboards → the logit folder → logit internals.
  3. Wait about ten seconds for data, because aggregate flushes on a 10s window.
  4. To follow a trace, open one from a Tempo: table panel, or expand a line in the Loki: raw demo traffic panel and follow its TraceID link.

Generate some traffic by hand

traffic (demo/compose.yaml) already drives a low-volume loop through these routes, but you can also trigger them directly:

  • /work: jittered latency and an occasional real 503.
  • /boom: always a real 500, with a real exception recorded on its OpenTelemetry span.

Both give the demo's Tempo traces a shape worth looking at, instead of a flat chain of 200s. traffic is a plain curl loop with no browser involved, so browser-originated telemetry only shows up once someone opens this page in a browser.

Unlike the plain link above, this goes through @opentelemetry/instrumentation-fetch (browser/telemetry.js). The resulting fetch span becomes a real parent of this call's own Django request span: one trace spanning browser → haproxy → nginx → app → Postgres/Celery.

How this page's own resources are traced

This page's document request carries the trace described above. Its sub-resource requests can't: no JavaScript runs before the browser issues a <script src> or <img> request, so that request can't carry an outbound traceparent header. Haproxy gives each one a fresh trace id of its own, unconnected to the page's.

The correlation runs backwards instead. Haproxy sends a Server-Timing: traceparent;desc="..." response header on every request, and the browser exposes it to JavaScript as PerformanceResourceTiming.serverTiming. The browser instrumentation reads it back and links each resource-load span to the exact logit-minted span that served it, lifted from a plain haproxy or nginx access log line.

This demo is not a production example

This stack shows a large portion of logit's functionality in a way that's quick to spin up. It is not an example of how to run any of this in production. Don't copy these shortcuts uncritically:

  • Grafana's anonymous access is admin-level, not read-only (GF_AUTH_ANONYMOUS_ORG_ROLE: Admin, demo/compose.yaml).
  • A hardcoded Django SECRET_KEY (demo/app/demoproj/settings.py) and a hardcoded Postgres password, POSTGRES_PASSWORD (demo/compose.yaml). VictoriaMetrics, Loki, and Tempo run with no authentication at all.
  • ALLOWED_HOSTS = ["*"] (same settings.py), because there's no single real hostname to pin for a stack that answers on localhost at whatever port you gave it.
  • logit runs as root so it can read Docker's own container log directory directly for nginx's access log and Redis's server log (docker_in, see demo/README.md). That's a real cost paid for two tiers' telemetry, not a default posture.
  • Postgres logs every statement (log_min_duration_statement=0, demo/compose.yaml) instead of sampling slow ones. This shows the mechanism, not a production logging policy.
  • No TLS between any of the tiers.
  • Every volume is disposable: docker compose down -v wipes all of them, and none are backed up.
